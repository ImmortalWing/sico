## 1. 一句话状态

STEP-0087 已完成：structured task scope 以 sequential executor 落地（async function/spawn/await/task group，E5101/E5102 typed 拒绝，Cancelled 域错误传播 122,evidence `docs/reports/script-task-sequential-v0.md`)。下一步 STEP-0088 是 async runner 与 streaming stdio:async Store、timeout/cancel、64 KiB 级块、有界队列与不做整段输出捕获——核心是把 cancel 送达**阻塞中的** host 调用（现在只在调用间观测）。

## 2. 已冻结事实（实现不得偏离）

- runner 现状（`runner/sico-runner/src/lib.rs`)：同步单线程;`link_fs`/`link_streams` host 调用阻塞；cancel 只在调用间/stream 循环间检查；epoch deadline 打断 guest;fuel/hostcall 每次 stream call top-up;wasm stack 4 MiB。
- RFC-0030 取消矩阵：blocked read/write 应收 `stream-error.cancelled`,runner 出 `Cancelled` 123——v0 只做到调用间观测，**阻塞中的取消是 0088 的主债**,STEP-0088 必须实测取消延迟（目标 <100 ms,M9 §9)。
- M9 §9 性能目标：persistent warm rerun ≤20 ms(0090)、取消 <100 ms、队列全有界。
- sequential executor(0087）是并行度 1 的 task 模型;`collect_tasks`/真 Future/Stream 类型仍 typed 拒绝。async runner 不需要先改语言层。
- 工具链:runner/MSVC 构建 `target\build-runner.bat`/`target\test-runner.bat`(cmd 必须 `//c`);WSL Ubuntu 可做 Linux 证据。

## 3. STEP-0088 执行顺序（建议）

1. 选型:wasmtime 46 的 Store 有 `call_async`?查 `Config::async_support` + `store.run_concurrent`/epoch;若 crate 级 async 不可用，用「host 调用跑 worker 线程 + channel 有界化」的同步折中（仍满足取消延迟，文档说明）。
2. blocked stdin read 的取消:self-pipe/线程 + bounded channel;cancel 时 read 返回 `stream-error.cancelled`,runner 出 123，实测延迟。
3. streaming stdio 不把输出整段入内存（现在 guest 侧 stdout 已是 stream;runner 进程 stdout 直通 ✓)，补慢消费者背压用例。
4. 取消延迟矩阵证据:blocked-read cancel、write-block cancel、pump cancel;报告 + validate-step-0088.ps1。
