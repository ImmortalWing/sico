## 1. 一句话状态

STEP-0077 已完成：独立 `I64/U64` 已贯通 semantics、verified IR、动态 Core Wasm 与 Component；2,048 × 8 Node oracle 和 Wasmtime 46.0.1 的 11 个 Component 边界用例全部通过，overflow/underflow 保持 typed `Result`，`Int` 未被静默缩窄。下一项 STEP-0078 负责 general function call 与 control/data codegen。

## 2. 已冻结契约

- 显式构造：`I64.literal(Int literal)`、`U64.literal(Int literal)`；当前不支持任意 `Int` 的运行时转换。
- checked 运算：`checked_add`、`checked_sub` 返回 `Result[fixed, NumericError]`；错误枚举为 `overflow`、`underflow`。
- 比较：`equal`、`less_than` 返回 `Bool`，signedness 由 verified operand type 决定。
- 普通 `+` 不适用于 `I64/U64`；`Int -> I64/U64` 不隐式转换。
- Core direct checked result 为 `(tag, payload)`；Component 使用 Canonical ABI 间接结果区并暴露真实 `result`。

## 4. STEP-0078 真实缺口

- backend 尚不发射 `Call`；多函数程序无法执行。
- entry `Jump`/`Match`、非 return branch block 和一般 CFG 仍 typed-refuse。
- `Construct`、`Project`、`Variant` 尚无 Core Wasm 内部布局；Component aggregate ABI 明确保留给 STEP-0079。
- 动态任意精度 `Int` 仍未实现；STEP-0078 应以 `Bool/I64/U64` 贯通控制流，不得借机把 `Int` 改为 i64。
- IR v0 无隐式 phi；开始前必须审计跨 block value/dominance 与 back-edge 可表示性，再冻结 reducible CFG 或 dispatcher strategy。

## 5. 推荐执行顺序

1. 枚举当前 lowering 实际产生的 `Call/Branch/Jump/Match/Construct/Project/Variant` 形状和 verifier 约束。
2. 先冻结 CFG 与 aggregate internal layout/refusal 边界，再改 codegen。
3. 先加 verifier/backend mutation 和 runtime oracle，再实现 direct calls 与控制流。
4. 用 Wasmtime 46.0.1 执行多函数、嵌套分支、循环与枚举 match fixture。
5. 更新 STEP-0078 报告后进入 STEP-0079 general aggregate Canonical ABI。

## 6. 不得误报

- numeric `Result` 的私有返回区不等于通用 record/list/string/result ABI。
- STEP-0077 只证明 Windows 上 Node/Wasmtime 的 fixed-width 路径，不证明 Linux/mobile 或 Script runner。
- M8、RFC-0029、ADR-0009 仍未完成/接受；manifest v1、adapter packaging、runner、CLI、cache、stdlib 均在后续步骤。
- M6 Android、M7 public production、真实第三方与 live-model 证据继续保持原 gate。
