## 1. 一句话状态

STEP-0078 已完成 direct function calls、通用 dispatcher CFG、Jump/Branch/Match/back-edge，以及函数内部 record/variant 扁平布局；Node 与 Wasmtime 46.0.1 的 7 个结果和 bounded-fuel loop trap 均通过。下一项 STEP-0079 只负责 Script aggregate Canonical ABI，不把内部 locals 冒充公开 ABI。

## 2. 已冻结实现边界

- IR `FunctionId` 从 1 开始，Wasm index 从 0 开始；backend 使用显式映射。
- IR v0 不允许跨 block instruction value，参数可在所有 block 使用；CFG 使用 private `i32` dispatcher local。
- back-edge 可发射；不终止程序由 Runtime fuel/timeout gate 截断。
- `Construct` 在 IR 中保存字段名，内部 record 扁平为 locals；`Project` 只读取已知本地 layout。
- variant tag 按模块内名称排序确定，payload 扁平跟随 tag；当前 match 只执行 Bool、wildcard、variant tag 与忽略 payload。
- aggregate 参数、返回值、Call transport、payload binding/inspection 明确 typed-refuse，留给 STEP-0079 或后续 lowering。
- 动态任意精度 `Int` 仍未实现，不能改为固定 i64。

## 3. STEP-0079 执行顺序

1. 从 `wit/script-profile-v0` 与 RFC-0029 生成一张唯一 layout/ownership/post-return 表。
2. 先实现 bounded arena 与 checked address arithmetic，并用恶意 memory fixtures 锁死拒绝路径。
3. 按 Text → Bytes → list<Text> → Script records → Result 的顺序实现 lift/lower。
4. 加入至少 10,000 个 seeded roundtrips、invalid UTF-8/tag/alignment/bounds mutation 和 repeated-call cleanup oracle。
5. 精确 Wasmtime Component 证据通过后，才开始 STEP-0080 compiler profile/adapter/manifest 集成。

## 6. 不得误报

- STEP-0078 的 flat locals 不是 Canonical ABI，也没有证明 Text/Bytes/List/record/Result 跨 Component 正确。
- fixed numeric `Result` 的私有 return area 不是通用 allocator、realloc 或 post-return 实现。
- STEP-0079 不包含 adapter composition、manifest v1、runner、CLI/cache、stdlib 或 M9 streaming/async。
- M6 Android、M7 public production 与真实第三方/live-model 外部 gate 没有变化。
