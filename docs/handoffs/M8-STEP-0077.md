## 3. 当前真实缺口

- IR 只有 `Type::Int`、`ConstInt` 与 `AddInt`，没有 `I64/U64`；
- backend 只在常量已证明 fit `i64` 时发射 `Int`，拒绝 `Int` parameters、非 constant copy/add；
- integer literal 当前语义类型为 `Int`，不能通过后端偷改为 `I64`；
- general call/control 属于 STEP-0078，aggregates/Canonical ABI 属于 STEP-0079，不应混入本步；
- RFC-0029 与 ADR-0009 仍为 proposed，composition GO 只完成架构 gate，不代表整个 Script profile 已接受或完成。

## 4. 下一条执行顺序

1. 审计 builtin type 与 literal/conversion 规则，确认如何显式获得 `I64/U64`；
2. 冻结 IR JSON 名称和 checked arithmetic/comparison operation set；
3. 先补 verifier mutation/oracle，再实现 dynamic locals/params/results；
4. 运行 source/IR/backend/Wasmtime fixtures，保存 boundary 与 property evidence；
5. 完成后再进入 STEP-0078 general call/control codegen。

## 5. 不得误报

- 不得把现有 `Int → i64` 常量优化扩展成隐式语言语义；
- 不得用 wrapping arithmetic 或裸 trap 冒充 checked typed behavior；
- STEP-0076 的 Adapter 仍是 Script-to-Script composition prototype，不是 WASI CLI adapter、manifest v1 或 production runner；
- M6 Android、M7 public production、live model 与真实第三方证据仍保持原 gate。
