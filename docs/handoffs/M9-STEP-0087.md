## 1. 一句话状态

STEP-0086 已完成：RFC-0030 streaming 端到端真实可用（`sico.stream.*` 九个 intrinsics、canonical resource 句柄、exact drop、mixing rule、256 MiB bounded-RSS passthrough、use-after-close trap 125），证据在 `docs/reports/script-streaming-v0.md`。下一步 STEP-0087 是 Task/Future/Stream 源级后端：structured task scopes、单终态 winner、cancellation edges 与有界 stream flow——重点是让 guest 侧能写真正的**循环/有界流**（现在的递归 pump 受 arena 累积与栈深度限制）。

## 2. 已冻结事实（实现不得偏离）

- streams 边界:`sico:script/streams@0.1.0`(read clamp 64 KiB、write ≤1 MiB all-or-error、pump host loop、stream-error 四值）。新能力一律走新接口，不改 0.1.0。
- 递归 pump 的天花板:arena bump 不回收(每块累积),4 MiB wasm stack(~8k 迭代)。STEP-0087 的 loop/flow 必须让 per-chunk transform 常驻内存有界。
- budget 模型:stream host call 每次 top-up(1M fuel / 64 MiB hostcall transport);epoch deadline 是最终非终止界。
- IR 已有 affine resource 骨架(Type::OwnedResource/BorrowedResource、ResourceMove/Borrow/Drop/ResourceCall 及 verify 强制),Task/Future/Stream 类型目前在后端是 typed refusal(lower_local_types 的 Task/Future/Stream arms)。
- RFC-0004 已接受:Task 属词法 scope、完成/timeout/cancel/host-failure 竞逐单终态、Stream 有显式容量。WASI 0.3 async 原型(`prototypes/resource-async`、`wit/async-flow-v0`)已验证 future/stream identity roundtrip 与 cancel/backpressure。

## 3. STEP-0087 执行顺序

1. 读 M9 计划 §6(async/cancellation model)与 RFC-0004;确定 v0 范围(建议:loop/flow 或 task scope 的最小可证子集,不要一次全做)。
2. 若做 source loop:IR 已有 dispatcher CFG back-edge(STEP-0078),需要 surface 语法(评审:loop/block 形式)→ lower → 让 per-chunk transform 不再递归;arena 需要跨迭代回收策略(mark/reset 或专用 scratch 区)。
3. 若做 Task scope:Task 句柄类型、scope 退出 join/cancel、单终态仲裁,先写 RFC 增补再实现。
4. 证据:bounded stream flow(超出 arena 容量仍 passthrough/transform)、cancellation edges、负例(脱离 scope 的 task 拒绝)。
