## 2. M8 冻结事实（M9 不得破坏）

- Script WIT `sico:script@0.1.0`（`wit/script-profile-v0/world.wit`）：types + program world（imports: fs-read/fs-write; export run）。M9 streaming 应新增版本化接口而不是改 0.1.0 语义；buffered M8 entry 保持兼容 profile。
- adapter digest `185ebf1d…502c7`、manifest `sico.sapp.manifest.v1`、cache domain `SICO-SCRIPT-SOURCE-CACHE-V0` —— 改动任一即全部 cache identity 变化，需要明确版本步进。
- Canonical ABI:`ScriptAbi` 从 WIT 派生并 panic-on-drift;fs 通道的 transport-module 模式（独占 memory + 单一 bump allocator）是 M9 stream 传输可复用的先例。
- runner:one Store per call、typed outcomes、fuel/timeout/memory/cancel、fs grants;instances 上限 2。M9 async runner 是新执行模式，不应削弱这些不变量。
- 语言限制（M9 可攻关）:`case ok(x)` 仅限参数 subject;match arm 单 return、match 必须是函数首语句；无顶层语句（STEP-0092 决策）；无 closures。
- 性能基线（Windows release):`sico run` cold P95 46.96 ms / warm 44.82 ms / runner-only 29.00 ms;prototype in-process composed cold 15.80 ms / warm 0.20 ms。M9 persistent runner（STEP-0090）主攻 ~27–36 ms 的 per-process floor。

## 3. STEP-0085 执行顺序

1. 读 `docs/plans/M9-streaming-async-interactive.md` §5 streaming model 与 RFC-0004（resource/async mapping）+ `wit/async-flow-v0`/`wit/boundary-probe-v0` 既有草稿。
2. 起草 RFC（编号顺延，约 RFC-0030）：versioned `sico:script/streams@0.1.0` InputStream/OutputStream resource、read/write/flush/close 的 result 语义、EOF≠error、backpressure 边界（64 KiB-class chunks）、cancel 传播、与 M8 buffered profile 的共存规则。
3. RFC 必须含：ownership/drop 精确语义（no use-after-close、no cross-Store retention）、WIT 草稿、failure/cancellation 矩阵、与 runner typed outcomes 的映射。
4. 契约评审后再进 STEP-0086 实现。
