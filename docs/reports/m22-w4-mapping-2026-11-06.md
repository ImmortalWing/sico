## 1. 要回答的问题

STEP-0561 实测 150 项 `rust_check=refused` 语料 **verdict parity 147/150**（146 `match` + 归因后 1 真实声音洞 `missing-field/E2010` + 3 燃料墙）。但 guest 的 44 个 `E-SH-IR-*` 诊断码与 Rust 的 `LEXICAL`/`E-code` 命名空间不相交，**精确 `(id, span)` parity 未达**。本片回答：

> 能否建立一个**有证据支撑**的 guest `E-SH-IR-*` ↔ Rust `LEXICAL`/`E-code` 映射契约，使 `(verdict, mapped-id)` 轴可精确出账？span 轴现状如何？

## 2. 证据事实（实测，本片前提）

本片先核实了三条**决定映射可行域**的事实，全部来自实际执行：

1. **Rust oracle 有 span，冻结语料没有。** `sico check --json` 对每条诊断发射完整 `code` / `key` / `range.line:col:byte`（实测 `use-after-move.sico` → `E1013` / `SYNTAX_UNEXPECTED_TOP_LEVEL` / `5:1:102`）。但 `selfhost/corpus-v0.json` 的 `diagnostic_ids` 是**粗分类**：`tools/update-m22-corpus.ps1:192-204` 仅对纯文本 check 输出跑正则 `\bE\d{4}\b`，取不到 E-code 时回退 `LEXICAL`/`SYNTAX`/`UNCLASSIFIED`，**不含 span**。所以冻结基线本身只有 `(rust_code 粗类)`，无 span。
2. **guest 无 span。** guest 编译器经 runner 返回 `{"class":"domain-error","detail":"...ERR:E-SH-IR-FUNCTION-COUNT"}`（实测），只有裸码，**无位置信息**。⇒ span 比较缺一侧输入，**结构上不可达**。
3. **Rust E-code 与 guest 码的对应是可观测的。** 把冻结 parity 工件的 `(rust_diagnostic_ids, guest_verdict)` 配对，得到 **33 个唯一 `(rust_code, guest_code)` 对**，其中 32 个是具体 `E-code ↔ 具体 E-SH-IR-*`（refined），1 个是 `LEXICAL ↔ E-SH-IR-FUNCTION-COUNT`（coarse，98 项）。

## 3. 方法

### 3.1 映射工件 `selfhost/corpus-parity-map-v1.json`（新 schema）

- schema `sico.m22.corpus-parity-map.v1`，`version: 1`，字段 `rust_code` / `guest_code` / `grain(refined|coarse)` / `equivalence_class` / `evidence{corpus_count, sample_paths, source}`。
- **只登记有冻结语料证据的等价类**（`evidence.corpus_count ≥ 1`，sample_paths 取前 3 条确定性路径）。宁缺毋滥：**无证据的码对一律不登记**，留给 §4.3 缺口清单。
- 工件内 `.span_axis` 显式写明 span 轴 `blocked-guest-side` 及原因（§2.1/2.2），**不虚报 span parity**。
- 探针加载时**严格校验**：schema 名、version==1、非空、`grain ∈ {refined,coarse}`、无重复 `(rust, guest)` 对、无空码；畸形即 typed 拒绝 exit 1，不做静默近似。

### 3.2 探针扩展 `tools/probe-m22-corpus-parity.ps1`

- 逐条输出 `rust_verdict`（`REFUSED:<frozen id>`）、`guest_verdict`（`REFUSED:<code>` / `LOWERED` / `FAILED:<snippet>`）、`mapped_id`、`parity`。
- parity 三级：
  - `exact`：guest 拒绝**且** `(rust_id → guest_code)` 对已登记；
  - `structural`：guest 拒绝但该对**未**登记（仅 verdict parity）；
  - `zero`：guest 未拒绝 —— `LOWERED`（越权接受/声音洞）或 `FAILED`（燃料墙）。
- 报告工件仍写 `selfhost/corpus-parity-v0.json`（保持 schema `sico.m22.corpus-parity.v0`，供电池消费），新增 `mapped_by` / `exact_parity_count` / `structural_parity_count` / `zero_parity_count` / `mapped_id_coverage` / `span_axis` / `unmapped_rust_ids` 字段。
- `-RustSpans` 开关：额外跑 `sico check --json` 采集 **Rust 侧 span 作佐证**（不参与比较，因 guest 无 span 可比）。实测见 §2.1。

## 4. 结果（全量 150 项实测）

> 本节数字来自 §5 记录的全量探针运行（2026-11-06 本机）。运行日志与退出码见 §5。

全量运行（2026-11-06 本机，约 44 min wall）写入 `selfhost/corpus-parity-v0.json`，**实测**字段：

| 汇总 | 值 |
|---|---|
| `checked_count` | **150** |
| `exact_parity_count` | **147** |
| `structural_parity_count` | **0** |
| `zero_parity_count` | **3** |
| `mapped_id_coverage` | `registered_classes=33 (refined=32 coarse=1)` |
| `unmapped_rust_ids` | `[]` |
| `span_axis` | `not-compared`（guest 无 span） |

探针退出码 **`PROBE_EXIT=1`**（符合约定：`zero=3 > 0` ⇒ exit 1）。3 项 `zero` 全部为 `scope-nesting-limit.sico` 燃料墙（`future-task` / `syntax-candidates/b` / `syntax-candidates/c`），guest 均 `FAILED`（`resource-limit`/FuelExhausted），**原样登记，未上调限额**。

> 证据卫生：全量运行逐条 stdout 行因 PowerShell 重定向缓冲未落日志（`/tmp/parity-full.log` 0 字节），**权威记录为回写工件 `selfhost/corpus-parity-v0.json` 的字段**，已如实登记。全量运行期间一次并发的 `-Limit 2 -RustSpans` 验证曾把该工件覆盖成 2 项版本，已 `git checkout --` 复原，全量运行结束时以 150 项版本最终覆写。

### 4.2 span 轴

**未比较、未达标**。原因见 §2：Rust 有 span 但冻结基线无 span，guest 结构上无 span。`-RustSpans` 佐证采集确认冻结 `LEXICAL` 桶实际是 live `E1013 / SYNTAX_UNEXPECTED_TOP_LEVEL`（带真实 span），⇒ coarse 类 `LEXICAL ↔ E-SH-IR-FUNCTION-COUNT` 只是**粗分类塌缩**，不是 refined 语义匹配，**不得**读作 span 级等同。

### 4.3 仍缺的映射项

- **3 个燃料墙**（`scope-nesting-limit.sico` ×3：2×`LEXICAL` + 1×`E5105`）：guest `FAILED`（FuelExhausted，`resource-limit`），**无 refusal 码** ⇒ 无法纳入映射，**原样登记**，**不上调限额**。这 3 项即 `zero_parity_count=3` 的全部来源。
- **`LOWERED`=0（本片实测）**：本片全量运行未出现 guest 越权接受，故无「声音洞」型映射缺口。
- **`unmapped_rust_ids=[]`（实测）**：147 个 guest 拒绝项全部命中登记映射类，无「拒绝但未登记」的结构 parity 项。
- **span 轴整体缺失**：所有 150 项都无 span 比较（§4.2），这是映射契约当前最大的未闭合面。
