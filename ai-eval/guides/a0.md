# Sico candidate A0 guide

- `newtype Name = Base` declares a nominal type.
- `record Name` and `enum Name` use indented members and close with `end`. Record fields are bare `name: Type` lines; enum variants are bare `Variant` lines, with a named payload written `Invalid(value: Text)`.
- Functions use `fn name(parameters) -> ReturnType`, an indented body, and `end`.
- Every function result is returned with `return`.
- Record and variant payload construction uses `Type(field: value)` or `Variant(value)`.
- Generic types use `Type<A, B>`, for example `Result<Int, ParseError>` and `List<Int>`.
- A match statement uses `match value`, arms written as `Pattern => return value`, and `end`. Patterns always qualify the variant with its enum name, for example `Color.Red => return "red"`. Inside an expression context an arm yields a value without `return`, as in `.map_error(problem => match problem ... end)`.
- A successful Result is `ok(value)`; explicit error mapping is `.map_error(problem => match problem ... end)`.
- `capability`, `resource`, and `interface` declarations use indented members and close with `end`. Their members are bare signatures such as `fn write(text: Text) -> Result<Unit, ConsoleError>` with no body.
- Async functions add `async` before `fn`; `using value ... end` gives deterministic cleanup and `task group ... end` gives structured concurrency. A spawned task is bound with `let name = spawn call(...)` and observed with `await`.
- Exported effectful functions add `export` directly before `fn`, followed by indented `effects ...` and `capabilities ...` declarations (one entry per line) before executable statements.
- Resource methods write `borrow self` for a borrow and `self` for a consuming receiver.
- Use the exact declaration and member order requested by the task.

## Canonical layout

Output is compared byte-for-byte against a canonical reference, so layout matters:

- indent with exactly 2 spaces per level; never use tabs;
- exactly one blank line between top-level declarations; no blank lines elsewhere;
- `export` stays on the same line as the `fn` it modifies; `effects` and `capabilities` are single indented lines, not nested blocks;
- no comments and no trailing whitespace; the file ends with a single newline.

## Complete example

```sico
record Point
  x: Int
  y: Int
end

fn origin() -> Point
  return Point(x: 0, y: 0)
end

capability Clock
  fn now() -> Int
end

export fn tick(clock: Clock) -> Int
  effects clock.now
  capabilities clock
  return clock.now()
end
```
